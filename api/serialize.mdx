The `Serialize` trait is the entry point for the serialization half of Serde's data model. Any type that implements `Serialize` can be converted into any data format that has a corresponding `Serializer` implementation — JSON, YAML, Postcard, TOML, and many others — without knowing anything about the target format. Serde ships with implementations for a wide range of standard library types, and the `#[derive(Serialize)]` macro generates correct implementations for most user-defined structs and enums automatically.

## Trait definition

```rust
pub trait Serialize {
    fn serialize<S>(&self, serializer: S) -> Result<S::Ok, S::Error>
    where
        S: Serializer;
}
```

The single required method, `serialize`, is called with a concrete `Serializer` chosen at the call site. The method must call exactly one of the `Serializer`'s methods to map `self` into Serde's data model. The return type `Result<S::Ok, S::Error>` uses the associated types of the `Serializer`, so the output type and error type are entirely determined by the chosen format.

## When to implement

You need to implement `Serialize` when:

- You have a type not covered by the built-in implementations listed below.
- You want to change how an existing type serializes (for example, serializing a newtype wrapper differently from its inner value).
- You are wrapping a type from another crate that does not ship Serde support.

In the vast majority of cases, `#[derive(Serialize)]` is the right approach. Manual implementation is only necessary when the derive output would be incorrect or insufficient.

<Tip>
  Third-party crates can provide `Serialize` implementations for their own
  types. For example, the `linked-hash-map` crate provides `Serialize` for
  `LinkedHashMap<K, V>` so it works with any Serde format out of the box.
</Tip>

## Using the derive macro

For structs and enums in your own code, the `#[derive(Serialize)]` procedural macro generates a correct `Serialize` implementation automatically. Add `serde` to your `Cargo.toml` with the `derive` feature enabled:

```toml
[dependencies]
serde = { version = "1", features = ["derive"] }
```

Then annotate your type:

```rust
use serde::Serialize;

#[derive(Serialize)]
struct Point {
    x: f64,
    y: f64,
}

#[derive(Serialize)]
enum Direction {
    North,
    South,
    East,
    West,
}
```

The generated code calls the appropriate `Serializer` methods for each field and variant, matching the Serde data model exactly. Derive attributes such as `#[serde(rename = "...")]`, `#[serde(skip)]`, and `#[serde(flatten)]` give you fine-grained control over the output without writing any serialization logic by hand.

## Manual implementation example

When `#[derive(Serialize)]` is not suitable, implement the trait directly. The example below shows what the derive macro would generate for a simple struct — it serializes `Person` as a three-field struct using `SerializeStruct`:

```rust
use serde::ser::{Serialize, SerializeStruct, Serializer};

struct Person {
    name: String,
    age: u8,
    phones: Vec<String>,
}

impl Serialize for Person {
    fn serialize<S>(&self, serializer: S) -> Result<S::Ok, S::Error>
    where
        S: Serializer,
    {
        // "3" is the number of fields in the struct.
        let mut s = serializer.serialize_struct("Person", 3)?;
        s.serialize_field("name", &self.name)?;
        s.serialize_field("age", &self.age)?;
        s.serialize_field("phones", &self.phones)?;
        s.end()
    }
}
```

<Note>
  A `Serialize` implementation must call **exactly one** top-level `Serializer`
  method. Calling more than one, or none at all, is incorrect and may produce
  unexpected results or errors.
</Note>

### Choosing the right Serializer method

The method you call determines how the data model represents your type:

| Rust type shape | Serializer method |
|---|---|
| `bool`, integers, floats, `char`, `str` | `serialize_bool`, `serialize_i*`, `serialize_u*`, `serialize_f*`, `serialize_char`, `serialize_str` |
| `[u8]` byte slice | `serialize_bytes` |
| `Option::None` | `serialize_none` |
| `Option::Some(v)` | `serialize_some(&v)` |
| `()` | `serialize_unit` |
| `struct Unit` | `serialize_unit_struct("Unit")` |
| `enum E { A }` | `serialize_unit_variant("E", 0, "A")` |
| `struct Millimeters(u8)` | `serialize_newtype_struct("Millimeters", &self.0)` |
| `enum E { N(u8) }` | `serialize_newtype_variant("E", 0, "N", &n)` |
| `Vec<T>`, slices | `serialize_seq(Some(len))` |
| Tuples, fixed arrays | `serialize_tuple(len)` |
| `struct Rgb(u8, u8, u8)` | `serialize_tuple_struct("Rgb", 3)` |
| `enum E { T(u8, u8) }` | `serialize_tuple_variant("E", 0, "T", 2)` |
| `HashMap`, `BTreeMap` | `serialize_map(Some(len))` |
| `struct S { r: u8 }` | `serialize_struct("S", 1)` |
| `enum E { S { r: u8 } }` | `serialize_struct_variant("E", 0, "S", 1)` |
