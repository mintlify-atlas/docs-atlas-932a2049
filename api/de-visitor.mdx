The `Visitor` pattern is the heart of Serde deserialization. A `Visitor` is a type that knows how to construct a Rust value from each of the possible shapes data can take — booleans, integers, strings, byte arrays, sequences, maps, enums, and more. When you call `deserializer.deserialize_*`, the deserializer inspects the input and calls the appropriate `visit_*` method on your `Visitor`. This indirection means one `Deserialize` implementation works across every data format Serde supports.

## Trait Definition

```rust
pub trait Visitor<'de>: Sized {
    /// The Rust type this Visitor produces.
    type Value;

    /// Format a message describing what this Visitor expects to receive.
    ///
    /// Used in error messages. Complete the sentence
    /// "This Visitor expects to receive …".
    /// The message should not be capitalized and should not end with a period.
    fn expecting(&self, formatter: &mut fmt::Formatter) -> fmt::Result;

    // --- Primitive visit methods (all have default impls) ---
    fn visit_bool<E: Error>(self, v: bool) -> Result<Self::Value, E> { ... }

    fn visit_i8<E: Error>(self, v: i8)   -> Result<Self::Value, E> { ... }
    fn visit_i16<E: Error>(self, v: i16) -> Result<Self::Value, E> { ... }
    fn visit_i32<E: Error>(self, v: i32) -> Result<Self::Value, E> { ... }
    fn visit_i64<E: Error>(self, v: i64) -> Result<Self::Value, E> { ... }
    fn visit_i128<E: Error>(self, v: i128) -> Result<Self::Value, E> { ... }

    fn visit_u8<E: Error>(self, v: u8)   -> Result<Self::Value, E> { ... }
    fn visit_u16<E: Error>(self, v: u16) -> Result<Self::Value, E> { ... }
    fn visit_u32<E: Error>(self, v: u32) -> Result<Self::Value, E> { ... }
    fn visit_u64<E: Error>(self, v: u64) -> Result<Self::Value, E> { ... }
    fn visit_u128<E: Error>(self, v: u128) -> Result<Self::Value, E> { ... }

    fn visit_f32<E: Error>(self, v: f32) -> Result<Self::Value, E> { ... }
    fn visit_f64<E: Error>(self, v: f64) -> Result<Self::Value, E> { ... }

    fn visit_char<E: Error>(self, v: char) -> Result<Self::Value, E> { ... }

    // --- String visit methods ---
    fn visit_str<E: Error>(self, v: &str) -> Result<Self::Value, E> { ... }
    fn visit_borrowed_str<E: Error>(self, v: &'de str) -> Result<Self::Value, E> { ... }
    fn visit_string<E: Error>(self, v: String) -> Result<Self::Value, E> { ... }

    // --- Byte visit methods ---
    fn visit_bytes<E: Error>(self, v: &[u8]) -> Result<Self::Value, E> { ... }
    fn visit_borrowed_bytes<E: Error>(self, v: &'de [u8]) -> Result<Self::Value, E> { ... }
    fn visit_byte_buf<E: Error>(self, v: Vec<u8>) -> Result<Self::Value, E> { ... }

    // --- Option / unit / newtype ---
    fn visit_none<E: Error>(self) -> Result<Self::Value, E> { ... }
    fn visit_some<D: Deserializer<'de>>(self, d: D) -> Result<Self::Value, D::Error> { ... }
    fn visit_unit<E: Error>(self) -> Result<Self::Value, E> { ... }
    fn visit_newtype_struct<D: Deserializer<'de>>(self, d: D) -> Result<Self::Value, D::Error> { ... }

    // --- Compound visit methods ---
    fn visit_seq<A: SeqAccess<'de>>(self, seq: A) -> Result<Self::Value, A::Error> { ... }
    fn visit_map<A: MapAccess<'de>>(self, map: A) -> Result<Self::Value, A::Error> { ... }
    fn visit_enum<A: EnumAccess<'de>>(self, data: A) -> Result<Self::Value, A::Error> { ... }
}
```

## Required Members

### `type Value`

The Rust type that this visitor produces. Usually the same type as the enclosing `Deserialize` impl.

### `fn expecting`

```rust
fn expecting(&self, formatter: &mut fmt::Formatter) -> fmt::Result;
```

Fills in the blank in "This Visitor expects to receive ___". Serde uses this in error messages generated by the default `visit_*` implementations. The `Visitor` itself implicitly implements the [`Expected`](/api/de-error#the-expected-trait) trait through this method, which is why you can pass `&self` to `de::Error::invalid_type`.

## Visit Methods: Default Behaviours

Every `visit_*` method has a default implementation. Understanding the defaults tells you exactly which methods you need to override.

<Accordion title="Primitives: visit_bool, visit_i*/visit_u*, visit_f*, visit_char">

`visit_bool`, `visit_i64`, `visit_u64`, `visit_f64`, `visit_i128`, and `visit_u128` each return an `invalid_type` error by default.

The smaller integer variants forward to the 64-bit base:

- `visit_i8`, `visit_i16`, `visit_i32` → forward to `visit_i64`
- `visit_u8`, `visit_u16`, `visit_u32` → forward to `visit_u64`
- `visit_f32` → forwards to `visit_f64`

So if you only override `visit_i64` and `visit_u64`, your visitor will accept any integer size.

`visit_char` defaults to encoding the `char` as a one-character UTF-8 string and forwarding to `visit_str`. Override it only when you need distinct handling for a `char` versus a string slice.

</Accordion>

<Accordion title="Strings: visit_str, visit_borrowed_str, visit_string">

`visit_str` is the base string method; its default returns an `invalid_type` error.

`visit_borrowed_str` defaults to calling `visit_str`. Override it only when you want zero-copy deserialization — see the [Borrowed Variants](#borrowed-variants) section below.

`visit_string` (available on `std`/`alloc`) defaults to calling `visit_str` and then dropping the `String`. Override it when you can reuse an owned allocation.

<Note>
It is never correct to implement `visit_string` without also implementing `visit_str`. Implement neither, both, or just `visit_str`.
</Note>

</Accordion>

<Accordion title="Bytes: visit_bytes, visit_borrowed_bytes, visit_byte_buf">

`visit_bytes` is the base byte-array method; its default returns an `invalid_type` error.

`visit_borrowed_bytes` defaults to calling `visit_bytes`.

`visit_byte_buf` (available on `std`/`alloc`) defaults to calling `visit_bytes` and then dropping the `Vec<u8>`.

The same ownership rules apply as for strings: implement neither, both, or just `visit_bytes`.

</Accordion>

<Accordion title="Option: visit_none, visit_some">

`visit_none` signals the absence of an optional value. Default returns `invalid_type`.

`visit_some` receives a `Deserializer` from which the inner value can be deserialized. Default returns `invalid_type`.

</Accordion>

<Accordion title="Unit and newtype: visit_unit, visit_newtype_struct">

`visit_unit` signals a `()` value. Default returns `invalid_type`.

`visit_newtype_struct` receives a `Deserializer` for the wrapped inner value. Default returns `invalid_type`.

</Accordion>

<Accordion title="Compound: visit_seq, visit_map, visit_enum">

All three return `invalid_type` by default. Override `visit_seq` to handle arrays/tuples/sequences, `visit_map` to handle structs/maps, and `visit_enum` to handle enum variants.

</Accordion>

## Borrowed Variants

Three visit methods carry the `'de` lifetime directly on their argument:

| Method | Argument type |
|---|---|
| `visit_borrowed_str` | `v: &'de str` |
| `visit_borrowed_bytes` | `v: &'de [u8]` |

When a format can lend a reference directly into its input buffer — for example, a JSON string that contains no escape sequences — it will call `visit_borrowed_str` instead of `visit_str`. This allows a `Deserialize` implementation to store a `&'de str` that points directly into the original input with zero copying or allocation.

<Tip>
If you want your type to hold a `&'de str`, override `visit_borrowed_str`. If you are happy with an owned `String`, overriding just `visit_str` is sufficient — `visit_borrowed_str` will delegate to it automatically.
</Tip>

## Full Example

The following visitor accepts either a string or an integer and builds a custom `StringOrInt` enum. This pattern is common when a JSON field may contain either `"42"` or `42`.

```rust
use serde::de::{self, Deserialize, Deserializer, Unexpected, Visitor};
use std::fmt;

#[derive(Debug)]
enum StringOrInt {
    String(String),
    Int(i64),
}

struct StringOrIntVisitor;

impl<'de> Visitor<'de> for StringOrIntVisitor {
    type Value = StringOrInt;

    fn expecting(&self, formatter: &mut fmt::Formatter) -> fmt::Result {
        write!(formatter, "a string or an integer")
    }

    fn visit_str<E>(self, v: &str) -> Result<Self::Value, E>
    where
        E: de::Error,
    {
        Ok(StringOrInt::String(v.to_owned()))
    }

    fn visit_string<E>(self, v: String) -> Result<Self::Value, E>
    where
        E: de::Error,
    {
        Ok(StringOrInt::String(v))
    }

    fn visit_i64<E>(self, v: i64) -> Result<Self::Value, E>
    where
        E: de::Error,
    {
        Ok(StringOrInt::Int(v))
    }

    fn visit_u64<E>(self, v: u64) -> Result<Self::Value, E>
    where
        E: de::Error,
    {
        i64::try_from(v)
            .map(StringOrInt::Int)
            .map_err(|_| de::Error::invalid_value(Unexpected::Unsigned(v), &self))
    }
}

impl<'de> Deserialize<'de> for StringOrInt {
    fn deserialize<D>(deserializer: D) -> Result<Self, D::Error>
    where
        D: Deserializer<'de>,
    {
        deserializer.deserialize_any(StringOrIntVisitor)
    }
}
```

<Note>
`deserialize_any` works only with self-describing formats (JSON, YAML). If you need compatibility with non-self-describing formats (Postcard, Bincode), use a specific `deserialize_*` method such as `deserialize_str` or `deserialize_i64` instead.
</Note>

For a complete guide to writing `Deserialize` implementations by hand, see the [Implementing Deserialize](/impl-deserialize) section of the Serde manual.
